## 7. ADMIN保護マトリックス

| 操作 | 期待結果 | ブラックボックス結果 |
|---|---|---|
| USER → ADMIN | 許可 | OK |
| ADMINが複数存在する状態で他ADMIN → USER | 許可 | OK |
| 自分自身をADMIN → USER | 禁止 | OK |
| 最後のADMINをUSERへ変更 | 禁止 | 保留 |
| 他USER削除 | 許可 | OK |
| ADMINが複数存在する状態で他ADMIN削除 | 許可 | OK |
| 自分自身を削除 | 禁止 | OK |
| 最後のADMINを削除 | 禁止 | 保留 |

### 保留理由

`BB-UED-004` と `BB-UED-008` は、最後のADMINがログインユーザー本人になるため、

- 自分自身のADMIN権限解除禁止
- 自分自身の削除禁止

の条件と重複します。

そのため、「最後のADMINだから拒否された」という条件だけを画面から単独で検証できず、ブラックボックステストでは保留としました。

最後のADMIN保護そのものについては `TESTING.md` に記録しているService層のJUnitテストで補完しています。
