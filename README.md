# 会員管理システム

Spring Bootを使用して作成したWebベースの会員管理システムです。

会員情報の登録・一覧表示・検索・詳細表示・編集・削除に加えて、 Spring
Securityを利用したログイン認証とADMIN /
USERによる権限制御を実装しています。

また、JUnit 5 / Mockitoを使用したService層の単体テストを実装しています。

------------------------------------------------------------------------

## 1. 主な機能

### 会員管理

-   会員登録
-   会員一覧表示
-   会員詳細表示
-   会員情報編集
-   会員削除
-   会員検索
-   ページング
-   並び替え

### 検索条件

以下の条件で会員を検索できます。

-   名前
-   年齢
-   会員種別

会員種別：

``` text
一般
ゴールド
```

### 並び替え

以下の並び順に対応しています。

``` text
ID昇順
ID降順
名前昇順
年齢昇順
```

## 2. ログイン機能

Spring Securityを使用したログイン認証を実装しています。

ユーザーには以下の2種類の権限があります。

``` text
ADMIN
USER
```

### ADMIN

ADMINはすべての会員データを操作できます。

主な操作：

-   全会員の一覧表示
-   全会員の詳細表示
-   全会員の編集
-   全会員の削除
-   ログインユーザー管理
-   ログインユーザー登録
-   ログインユーザー編集
-   パスワード変更
-   ログインユーザー削除

### USER

USERは自分が所有している会員データのみ操作できます。

Service層でも所有者チェックを行い、他のユーザーが所有する会員へのアクセスを防止しています。

``` text
USER
  ↓
会員ID + 所有者ユーザー名
  ↓
対象会員取得
```

------------------------------------------------------------------------

## 3. ログインユーザー管理

ADMINはログインユーザー管理画面からユーザーを管理できます。

対応している機能：

-   ユーザー一覧
-   ユーザー登録
-   ユーザー編集
-   ADMIN / USER権限変更
-   パスワード変更
-   ユーザー削除

------------------------------------------------------------------------

## 4. ADMIN保護

管理者が存在しなくなることを防ぐため、以下の制御を実装しています。

### 自分自身の削除禁止

ログイン中のユーザーは自分自身を削除できません。

``` text
ログインユーザー
      ↓
自分自身を削除
      ↓
エラー
```

### 自分自身のADMIN権限解除禁止

ログイン中のADMINが自分自身を、

``` text
ADMIN → USER
```

へ変更することはできません。

### 最後のADMIN削除禁止

システム上にADMINが1人しか存在しない場合、そのADMINを削除できません。

### 最後のADMIN権限変更禁止

システム上にADMINが1人しか存在しない場合、

``` text
ADMIN → USER
```

への変更はできません。

これにより、システム上のADMINが0人になることを防止しています。

------------------------------------------------------------------------

## 5. パスワード管理

パスワードは平文では保存せず、Spring
Securityの`PasswordEncoder`を使用してハッシュ化して保存します。

``` text
入力パスワード
     ↓
PasswordEncoder
     ↓
ハッシュ化
     ↓
データベース保存
```

パスワード変更時も同様に、新しいパスワードをハッシュ化して保存します。

------------------------------------------------------------------------

## 6. 例外処理

独自例外を使用して、存在しないデータや許可されていない操作を処理しています。

主な例外：

``` text
MemberNotFoundException
AppUserNotFoundException
UserOperationException
```

### MemberNotFoundException

存在しない会員、またはUSERが所有していない会員へアクセスした場合に使用します。

### AppUserNotFoundException

存在しないログインユーザーを取得しようとした場合に使用します。

### UserOperationException

以下のようなユーザー操作を拒否する場合に使用します。

-   ユーザー名重複
-   自分自身の削除
-   自分自身のADMIN権限解除
-   最後のADMIN削除
-   最後のADMIN権限解除

### MemberServiceImpl


### AppUserService

ログインユーザー管理を担当します。

主な処理：

``` text

findById()
findByUsername()
update()
delete()
updatePassword()
```

------------------------------------------------------------------------

## 11. 検索処理

会員検索にはSpring Data JPAの`Specification`を使用しています。

検索条件：

``` text
名前
年齢
会員種別
```

USERの場合は、さらに所有者条件を追加します。

``` text
検索条件
   +
owner.username = ログインユーザー
```

これにより、USERの検索結果には自分が所有する会員のみ表示されます。

## 14. テスト

JUnit 5 / Mockitoを使用して単体テストを実装しています。

Service層だけでなく、Controller、Config、Exception、Modelについてもテストを実施しています。

主なテスト対象：

-   Service
    -   会員登録・取得・検索・更新・削除
    -   ADMIN / USER分岐
    -   USER所有者チェック
    -   ページング・ソート
    -   ログインユーザー登録
    -   パスワードハッシュ化
    -   ユーザー名重複
    -   ユーザー権限変更
    -   自分自身の操作制限
    -   最後のADMIN保護
-   Controller
    -   URLマッピング
    -   Validation
    -   リダイレクト
    -   Modelへの値設定
    -   ADMIN / USER判定
-   Config
    -   Spring Security設定
    -   初期ADMINユーザー作成
    -   初期ADMINが存在する場合に再登録しないこと
-   Exception
    -   各独自例外のハンドリング
    -   エラーメッセージのModel設定
-   Model
    -   Entity / Form / 検索条件などの基本動作

詳細なテスト仕様については`TESTING.md`を参照してください。

### JaCoCoカバレッジ

JaCoCoによるカバレッジ計測を実施しています。

現在の結果：

  対象           Instruction Coverage   Branch Coverage
  ------------ ---------------------- -----------------
  Service                        100%              100%
  Controller                     100%              100%
  Model                          100%               n/a
  Config                         100%              100%
  Exception                      100%               n/a
  全体                            99%              100%

業務ロジック、権限制御、例外処理などの主要なテスト対象は100%です。

全体のInstruction Coverageが99%なのは、Spring

`DemoApplication.main()`はアプリケーション起動用のコードであり、
カバレッジ数値だけを100%にするためのテストは追加せず、テスト対象外としています。
